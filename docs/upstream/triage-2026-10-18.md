## How to read this

- Every item has an ID (`A1`, `B3`, …). Approve items by ID, for example "approve A, B1–B9, D2".
- **Applies** says what happens when the pull request is merged onto our `main` today, checked
  locally with `git merge-tree`:
  - **clean**: no conflict.
  - **docs/tests**: conflicts only in `ROADMAP.md`, `docs/`, `AGENTS.md`, `README.md` or appended
    tests. Trivial to resolve.
  - **code**: conflicts in code we changed in NuxOffice (ribbon, tabs, dialogs, grid…). Needs a
    careful port.
- Size is lines added / removed, measured against upstream `main`.
- An approved pull request is merged with its author's commits kept (attribution), recorded in
  [`CHANGES.md`](CHANGES.md), and passes `cargo xtask ci` before it lands. Upstream code stays
  `MIT OR Apache-2.0`.

Upstream will likely never merge some of these (VBA is out of scope there, see ADR 0007). For us
that is the point: good work that upstream declines can still land in NuxOffice.
