### PR 1 — `nux/rtl-explicit-align`

**Title:** Grid: explicit Left/Right alignment keeps its side on a right-to-left sheet

**Size:** 1 file, +28 −2 (`crates/ui-egui/src/grid.rs`).

**Tests:** new unit test `explicit_left_and_right_keep_their_side_on_a_right_to_left_sheet`;
`right_to_left.rs` passes.

**Description:**

> On a right-to-left sheet, **Align Right** put the text on the left and **Align Left** on the
> right. Cells are painted left to right and the sheet is mirrored afterwards, so an explicit
> alignment got mirrored too. Excel keeps an explicit alignment on the side it names in either
> sheet direction; only General alignment follows the sheet direction.
>
> The alignment is swapped before painting (`painted_halign`), for straight and rotated text.
> General, Center, Justify and Fill are unchanged.
>
> Tests: `cargo test -p gridcraft-ui-egui` (unit test for the swap; the right-to-left tests pass).
>

### PR 2 — `nux/row-autofit-measured`

**Title:** Row AutoFit measures wrapped text with the drawing font

**Size:** 3 files, +136 −4 (`engine/src/cmd/format.rs`, `ui-egui/src/grid.rs`,
`ui-egui/tests/header_autofit.rs`).

**Tests:** engine `autofit_rows_takes_measured_heights_and_estimates_arabic_narrowly`; UI
`row_double_click_fits_wrapped_arabic_text`; the engine and UI suites pass (1014 tests).

**Description:**

> Double-clicking a row boundary didn't shrink a row of wrapped Arabic text. The engine's width
> estimate counted every non-ASCII character as a full em, but joined Arabic letters are about
> half an em. So the text wrapped into twice the lines it needs, and AutoFit set the row to that
> height.
>
> - The row-header double-click measures each cell's text with the font that draws it, wrapped at
>   the column's width as the grid wraps it. It passes the heights to `home.autofitRowHeight`
>   through a new optional `measured: {"7": px}` parameter. Rows with no text keep the engine's
>   font-based height.
> - The engine's own estimate, used while typing and from the CLI and MCP, now gives Arabic
>   letters 0.45 em and harakat none. Hebrew, accented Latin, Greek and Cyrillic get 0.55 em.
>
> This is the row counterpart of #1320 (column AutoFit with the drawing font).
>
> One existing test fixture changed. Its rows started at 60 px, which is exactly the measured
> height of three 11 pt lines (45 pt, as in Excel), so a fitted row didn't change. They now start
> at 90 px.
>

### PR 5 — `nux/sheet-groups`

**Title:** Sheet groups: Shift/Ctrl+click tabs, and edits repeat on every grouped sheet

**Size:** 6 files, +257 −3 (engine `lib.rs`, `cmd/sheet.rs`, `tests.rs`; UI `tabs.rs`,
`ribbon.rs`, new `tests/sheet_groups.rs`).

**Tests:** engine `grouped_sheets_repeat_edits_and_undo_in_one_step`; two UI tests (Shift+click,
Ctrl+click); the engine and UI suites pass (1015 tests).

**Description:**

> Excel groups worksheets with Shift+click (a run of tabs) or Ctrl+click (one more tab). Data
> entry and formatting on the active sheet then apply to every grouped sheet, and the title shows
> **[Group]**. GridCraft had no way to select several sheets (#991), and the tab menu's **Select
> All Sheets** did nothing.
>
> - **Engine:** `DocState::grouped`, with `sheet.group {sheets}` and `sheet.ungroup`. After a
>   cell, range, edit or home command, the same command runs on each other grouped sheet with the
>   same selection, as one undo step. Excluded are sheet-level and object commands: Insert Sheet,
>   Format as Table, conditional formatting, Find and Replace and Flash Fill. The group drops when
>   sheets are added, removed, renamed or moved, or when a sheet outside the group is activated.
> - **Tabs:** Shift+click and Ctrl/Cmd+click group sheets, and grouped tabs are white like the
>   active one. A plain click on a grouped tab keeps the group, unless every sheet is grouped.
>   **Select All Sheets** groups all sheets; with a group, the menu offers **Ungroup Sheets**.
> - **Title bar:** shows `[Group]` while sheets are grouped.
>
> Fixes #991.
>
> 🤖 Generated with [Claude Code](https://claude.com/claude-code)

## Review notes on open upstream pull requests

We merged these pull requests into NuxOffice (see [triage-2026-10-18.md](triage-2026-10-18.md))
and found the problems below. Each note is written to post as a comment.

### On #1809 (LAMBDA recursion answers #NUM!)

> Thanks for this. On Windows in debug builds,
> `a_lambda_that_calls_itself_without_end_is_num_on_a_small_stack` fails: the case that goes
> through MAP gives `#VALUE!` instead of `#NUM!`. The stack check fires while MAP evaluates its
> LAMBDA argument, and `lambda_arg` turns any non-function result into `#VALUE!`. Release builds
> pass because the check fires one level deeper there.
>
> A fix that also helps generally: let `lambda_arg` return
> `Result<Arc<Lambda>, CellError>`. When the argument evaluates to an error, pass that error on
> instead of `#VALUE!`. Its four callers (MAP, REDUCE/SCAN, BYROW/BYCOL, MAKEARRAY) then
> `return err(e)`. With that change the test passes in both profiles.

### On #1078 (Flatpak and XDG font folders)

> `unix_font_dirs_include_the_flatpak_host_and_xdg_folders` runs on Windows too. There `/data` is
> not an absolute path, so `data_home.filter(|d| d.is_absolute())` drops it and the test fails.
> Since it checks Unix paths, `#[cfg(unix)]` in place of `#[cfg(not(target_arch = "wasm32"))]`
> fixes it.

### On #974 (start the installed-font scan)

> With this branch, `theme::font_binding_tests::a_bound_installed_font_is_used_by_name` is flaky
> under the parallel test runner. `unparseable_font_files_are_rejected_not_fatal` calls
> `font_definitions()`, which rewrites the process-wide bound-family registry without taking
> `fonts::TEST_LOCK`, so the two tests race. Holding `TEST_LOCK` in that test fixes it.
>
> Also, `cell_family` now takes the context, so callers outside this PR need the extra argument
> (for example any AutoFit measuring code).

### On #1422 and #1175 (filtered rows)

> Both PRs add an identical `fn filtered_rows` to `engine/src/cmd/edit.rs`, so merging both fails
> to compile (E0428). Whichever lands second should drop its copy.

### On #1395 and #972 (temporary-file save)

> Both rewrite `io::write_file` to save through a unique temporary file, in different ways, and
> they conflict. #1395's version plus #972's AutoSave failure feedback worked well together for us.
> Suggest rebasing #972 onto #1395, keeping only the AutoSave part.

### On #1666 and #1434 (R1C1-like names)

> Both add an `is_r1c1` check to `engine/src/cmd/formulas.rs`. #1666's version is stricter: it
> checks the row and column bounds and allows a `.` after a row number. #1434 needs the function
> to be `pub(crate)` for table names. Suggest #1434 reuse #1666's function once it lands.

### On #1816 and #1576 (GNOME Wayland window controls)

> These two are alternatives: both add `winit` with an Adwaita client-side-decoration feature.
> #1576's `wayland-csd-adwaita-notitle` needs no title font, which avoids the fallback-font
> problems in #54. It may be worth choosing one and closing the other.
